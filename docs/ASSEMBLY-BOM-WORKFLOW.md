## 当前工程师包的支座组合

本轮限定3种独立、非家族毫米零件及5个直接组件实例，包含重复放置的同一零件。
沿用已支持的原生孔、恒定圆角、来源明确的材料与尺寸公差，不新增建模或workflow范围。
BOM、组件身份、实际变换、约束及完整几何分别独立读取；数量、体积或外观相符不能替代这些检查。

R32已将同一支座桥板左孔改为10±0.15mm，保持右孔6mm、五实例及BOM 2/2/1。
完成四份修改文件保存、六模型正常关闭和精确重开；编辑入口另做预览，没有再次修改孔径。
这是当前保存基线，不是下一任务必须重复的孔径往返。
已支持的驱动孔径变更需有真实owner、类型、单位及reference、relation证据。
孔径编辑后的实际纸面`at`和范围可能与冻结前不同。
保留各次观测和失败，不据此确定SDK内部原因、宣称位置保护或静默略去差异。
保存零件不自动证明装配和图纸已保存；正常关闭重开、继续编辑及独立使用未完成时，不能写成通过。

保存、关闭和重开也要为整个CLI调用选择预算。确认会重新读取模型、依赖及授权，
并留存记录；预算不只是一个CAD函数的等待时间。
R31最后一个plate关闭曾在默认30秒预算下停止，原失败保持。
独立核实该关闭未越过派发前检查、当前plate仍为clean后，才用新计划完成剩余关闭。
该剩余生命周期明确使用`--timeout 120`，预览和确认都带相同预算。
120秒是本例选择，不保证所有模型、历史量或界面状态都能完成。
读取未决时先停止；具体区别见[执行预算和剩余任务](WORKFLOW-BUDGET.md)。

三零件共有6项基础尺寸语义未分类，保留完整原始状态并严格比较，不补默认值或忽略变化。
未分类不表示无单位、无作用或不活动，也不构成特征删除的完整保护结论；这些是普通返回，不是pending。
现有5个general view的alignment依赖不完整。
A4另2个projection view的依赖完整。
原生注释partial、尺寸显示incomplete及另行登记保持；范围缺失时不把空框当零尺寸。
PDF每页人工查看与自动布局检查分列，人工通过不升级旧REF或不完整回执。

R31及R32的A4图纸打开回复均出现8条尺寸框的16个坐标与后续独立读回不同。
同一组打开与随后读取之间，anchor、数值和公差相同，但其中7条不是目标孔径标注。
只针对目标标注的范围规则不能用于另外7条；全过程的尺寸框保护仍不完整。
这些框都来自原生GetEnvelope，原因尚未确认，不能写成估算框、font cache或刷新已解决。
保留即时回复和后续每次读回；不要通过移动标注或重放操作来消除记录。
最终PDF人工查看只检查当前页面可读性，不能替代这项跨时点保护。

绘制前读取[图纸范围合同](DRAWING-READING-CONTRACT.md)中的有限提醒。
R5尺寸框只作为本次观测的候选范围，不能因两次相等升级为稳定或完整。
预览逐页列出单位、已检查对象及未检查项；精确轮廓、引线、尺寸线和缺失读回仍要单列。
新任务仅对已核实的当前保存副本授权一次明确变更；历史配方和已完成的8→9mm不授权重放。

STEP保持独立blocked，不用原生工程或PDF通过替代交换文件验收。
各阶段是否完成，以交付绑定的实际证据为准；配方本身不构成保存重开或独立使用通过。
保持58/71、beta/FCC partial。

## 装配说明与续编

当前任务沿用上述三种零件、五个直接实例和两张原图纸。
保持10±0.15mm及BOM 2/2/1，采用命名平移爆炸状态表达拆装关系。
固定一个实际实例，其余实例按明确向量分离；不以修改正常装配位置或约束来代替爆炸状态。
具体步骤及保存重开判据见[装配说明图配方](ASSEMBLY-INSTRUCTIONS-WORKFLOW.md)。

新增说明图优先采用单页毫米A3、正常参考视图、爆炸视图、一个原生BOM表及简明说明。
同页独立表达、实际投影及保存后的关联，都要在该工程中核实，不能仅凭接口存在宣称通过。
每个视图的实际爆炸Boolean与装配当前命名状态分开读取；逐视图命名状态引用仍未检查。

BOM以实际repeat region、单元格模型引用及occurrence集合核对2/2/1。
只在一个目标视图生成气泡；逐项保留项号、数量来源、模型、根装配、组件路径和引线视图。
原生气泡创建来源与这些独立关联可支持有限工程结论。
当前尚未独立证明气泡专有类型和直接note-to-table链接。
不能把数字引线注释当完整原生类型证明。
已有其他视图覆盖的BOM气泡组合仍拒绝，不用普通数字注释替代原生生成。

装配说明图不重复全部加工尺寸。原关联零件图继续承担尺寸和公差表达；
新说明必须标明合成验收样件，不添加未经确认的扭矩、配合、紧固或制造要求。
布局提醒只使用身份唯一且有页、单位和范围来源的对象。身份歧义与未读范围逐项列为未检查。
PDF当前可读、对象关联、自动布局覆盖和旧尺寸框跨时点保护分别给结论。

## R7历史配方

本文面向维护 creo-cli 的开发者，假设已了解仓库的范围文件、两阶段写入和 operation 查询。
版本保持 1.1.0-beta.1。第七轮收尾完成一个合成装配的限定工程流程，当前限制和证据见
[收尾摘要](https://github.com/fatecannotbealtered/creo-cli/blob/6d93cf09f74c107ae80970838e136ce69ce328a2/docs/evidence/round7-closeout-20261009/README.md)。以下步骤需要独立自有工程及实际读回的 ID。

## 前提与范围

- 使用已授权的自有工程目录，保留原始版本文件。Creo 实例、历史 unknown 和用户模型保持原状。
- 替换限定已加载的同一家族 generic/instance；明确指定顶层 occurrence ID。
- BOM 限定一个装配模型、1..10 个直接零件实例、mm 单页图纸和单分段表格。
- 当前仅接受 Creo 库 `Assembly/bom_description_down.tbl` 的已核实字节，或工作区内的同字节副本。
  SHA-256 为 `5fa5852852a3f9f21e2faeb725012e6bc12ec0c958f511a7f83546a05a1b01ee`。
  不在仓库中分发该 PTC 模板。实际文件路径、文件身份、字节摘要均进入预览。
- 加载与候选源码匹配的组件。BOM 要求 `bom_reference_readback >= 2`，标题栏要求
  `title_projection_arcs >= 2`；缺少能力会拒绝。health 不代替加载来源及工程读回。
- 不支持本轮创建式或动态 ID workflow。表格创建后，先查询 ID，再预览气泡。

## 阶段操作

1. 读取 `assembly component list`、`family-table show`、零件尺寸和装配质量属性，固定输入及预期。
   `scripts/prepare_round7_assembly.py` 记录准备过程。`scripts/prepare_owned_family.py` 仅为已授权的
   自有样件在当前进程启用既有 family adapter 的公共运行时，保留 scope、unknown、token 和回执；
   不能把该准备工具当作公开 family-table 迁移。
2. 创建图纸并规划区域。当前样例 FRONT 中心为 [130,200] mm、ISOMETRIC 为 [310,200] mm，比例 2:1。
   BOM 左上角为 [10,95] mm；标题栏完整范围为 [235,5]–[415,37] mm。
   气泡视图预留 30 mm 外围区域；可判断的视图／表格冲突在预览中拒绝，文字与引线仍需全页复核。
3. 对 `drawing bom add` 预览、确认并读取表格。两条数据记录的完整外形为
   217.043×22.86 mm；变为三条记录时高度为 30.48 mm。核对 native region、模型引用、项号、数量。
4. 用实际表格 ID 对 `drawing bom balloons --view FRONT` 单独预览、确认。
   核对每个气泡的项目、数量、引线模型、根装配、occurrence 路径和视图。数量库存或圆圈外观不构成通过。
5. 对 `assembly component replace` 使用明确 ID 和 `--with`。预览绑定旧／新模型及其递归依赖、
   generic 文件版本。确认后独立读取新依赖树，逐项比较未替换实例及约束引用。
6. 保存模型，再保存、关闭并重新打开关联图纸，核对 BOM 数量变化与引线引用。
   当前样件实测项号 1→实例 40、项号 3→实例 41、项号 2→实例 48，各数量 1。
7. 通过 `drawing title-block apply` 写入明确的测试名称／编号；材料、绘制人和审核人留空。
   保留 REF 和 mm 说明。独立读取两条 0..2π 圆弧，并实际渲染检查文字及投影符号。
8. 导出 STEP/PDF。`scripts/consume_round7_step.py` 用独立 OCCT 进程验证文件单位、三实体体积和边界。
   PDF 每页用 Poppler 渲染；文字框自动检查与全部页面的视觉判断分别留档。

查询参数和请求结构以 `reference --command` 为准。例如，以下两次调用参数相同，确认值来自首次预览：

```text
creo-cli assembly component replace --model <自有装配.asm> --component <已读回 ID> --with <同族变型.prt> --dry-run
creo-cli assembly component replace --model <自有装配.asm> --component <已读回 ID> --with <同族变型.prt> --confirm <预览令牌>
creo-cli drawing table list --model <自有图纸.drw>
creo-cli drawing bom balloons --model <自有图纸.drw> --table <实际表格 ID> --view FRONT --dry-run
```

## 失败与接续

先用本地`operation show`检查原记录和停止指引。
若必需原生读取已开始或可能仍在运行，先停止该实例后续CAD派发；只做本地查看、process-only health和OS观察。
这些观察不证明getter结束。
不能立即运行模型读取、CAD query或resolve，也不能换Client作为恢复。
独立确认原调用及实例状态后，才进入正常原生目标读回和登记。
普通unknown写记录本身不等于整个实例有pending读取；仍按实际目标、依赖和派发事实判断。
部分应用、回复丢失和最终回执失败均不自动重放。
以独立模型／文件读回登记已知结果后，只执行明确的剩余操作。原始失败记录与文件版本保持不变。
`scripts/run_round7_faults.py` 在自有装配上检查真实保存后丢回复及最终父回执 I/O 故障。
准备、绘图、替换脚本按阶段停止并保留现场；失败脚本不能从头直接重跑到同一批模型。

第七轮收尾已通过现有 Auxiliary Applications 路线加载最终 Java application，无需重启 Creo。
最终来源及闭环证据见 [收尾结果](https://github.com/fatecannotbealtered/creo-cli/blob/6d93cf09f74c107ae80970838e136ce69ce328a2/docs/evidence/round7-closeout-20261009/README.md)。
仅支持一个原生 BOM 表格；其他视图已有关联 BOM 气泡时，拒绝 Creo 的逐组件数量转换。
其他视图的无关数字引线注释不参与本次覆盖。失败后的完整放置读回及明确剩余动作见
收尾边界 (historical material retained outside this snapshot)。不清理用户模型或历史 unknown。
