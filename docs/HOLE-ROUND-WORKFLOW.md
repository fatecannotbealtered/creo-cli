# 原生孔与外边圆角安装板

本指南限定 80×50×6 mm 合成安装板、两枚简单 Φ6 贯通孔，以及一条厚度方向外边的 R1
恒定圆角。以左下角为设计原点，孔中心为 (20,25)、(60,25) mm；本例原生坐标分别为
(-20,0)、(20,0)，板范围为 [-40,-25,-6]～[40,25,0]。不添加材料、公差、制造标准或签核。
当前参数以 `reference --command "feature hole"` / `feature round` 为准。

最终限定结果和故障矩阵见[第十轮证据](https://github.com/fatecannotbealtered/creo-cli/blob/6d93cf09f74c107ae80970838e136ce69ce328a2/docs/evidence/round10-20261010/README.md)。
脚本只负责本机获准的独立工作区，使用当前最终 EXE、新案例名和新的状态文件；
既有状态文件代表已执行历史，不能当成从头重跑入口。

## 先核对引用和符号

先用 `geometry list` 读取当前实体的面和边，记录 ID、法向、位置、范围和所属特征。
孔的偏置沿参考面的法向带符号；左面法向为 -X、底面法向为 -Y，因此本例两孔的偏置为
(-20,-25) 和 (-60,-25)。设计尺寸仍是正的 20、60、25 mm；API 偏置符号不改变设计意图。
读取预览的 `machining_intent.center`，与冻结的模型坐标逐项核对，再确认。

已实测：在左/底面上输入正的 20/25，Creo 可生成 active 的原生 Hole，但其轴在板外，
实体未被切除。特征自己的圆柱子对象、setter 返回值和体积估计不能单独证明打孔成功。
本候选检查当前实体上的孔面、轴线、半径和贯穿范围，另读原生特征定义的深度类型及引用。

圆角选取左下角那条长度 6 mm 的当前外边。不要照抄本地案例的边 ID。
圆角定义会保留创建前的边引用，而被圆角取代的边不再是当前实体边；这两种读回分别记录。
后续新操作必须重新取得当前几何。预览绑定模型、依赖、请求字节/文件身份和引用快照，
确认前漂移会拒绝。

## 编辑、重开和独立消费

通过公开 CLI 创建空白零件、原生矩形拉伸、两枚 `feature hole`、一个 `feature round`。
调用方先读回真实 ID，再传入下一步；不用动态 workflow。
保存关闭重开后检查原生 Hole/Round 类型、状态、尺寸及定义，修改孔径 6→8→6 mm，
圆角半径 1→1.5→1 mm，并核对无关尺寸和特征。

关联图纸为单页 A4、mm、第一角投影。先规划视图与标注区域，读取移动预览中的
`annotation_feedback`；已有原生文字框能提示重叠和可能的视图边界相交，但不能证明引线走向。
保留真实关联的参考尺寸及 REF 表达。每次关键孔径变化后保存、重开零件和图纸，核对关联值、
孔组的水平/竖直位置和完整图面。

STEP 用独立 OCCT 进程检查 mm、一个有效实体、孔轴/半径、整体范围和体积，并用沿孔轴的射线
检查是否被实体阻挡。理论体积为 `80×50×6 − π×(D_A²+6²)/4×6 − (1−π/4)×R²×6`。
比较容差为长度 0.001 mm、体积 0.05 mm³，它们是数值验收容差，不是制造公差。
PDF 必须逐页渲染，解码/文字页内检查和全页目视分开记录，重点检查孔径、宽度尺寸、引线及轮廓。

## 分阶段复跑

先设置获准的工作区、scope、服务 URL/token 文件，以及 `CREO_CLI_TEST_BINARY`。
本机脚本通过 `scripts/engineering_cli.py` 读取这些环境值；调用前会比较 EXE 内全部产品
代码对象、入口与 schema/changelog 资源，来源不匹配就停止。用唯一的新 `<run>` 与 `<state.json>`：

```text
python scripts/run_hole_round_case.py --name <run>-part --state <state.json> --stage build
python scripts/run_hole_round_case.py --name <run>-drawing --state <state.json> --stage drawing
python scripts/run_hole_round_case.py --name <run>-8 --state <state.json> --stage diameter8
python scripts/run_hole_round_case.py --name <run>-6 --state <state.json> --stage restore6
python scripts/run_hole_round_faults.py --name <run>-faults --state <state.json>
```

`build` 内已包含半径往返和保存重开。`finish-build` 只用于独立核对已创建特征后的明确剩余动作，
不是自动恢复，也不能在未核对状态时调用。每阶段完成后检查 `RESULTS.json` 和原生读回，
取得明确 ID 后再执行下一段。最终保存文件在状态文件 `files`，导出路径在 `exports`。
故障脚本复制最终零件，不改合格样件。失败不能仅看最后一个命令或忽略清理错误。

三个状态的 STEP/PDF 分别执行以下独立检查；`--diameter-a` 为对应的 6 或 8：

```text
python scripts/consume_hole_round_step.py --python-path <OCCT-python目录> --input <文件.step> --output <新报告.json> --diameter-a 6
python scripts/inspect_pdf_pages.py --input <文件.pdf> --output <新渲染目录>
```

PDF 检查脚本需要 Poppler 在 PATH 中。自动报告的目视状态保留 pending；
agent 逐页实际查看完整渲染图片后，另记文字/引线/轮廓与 REF 的判断及 PDF 摘要，不能把自动状态改称目视完成。

## 故障与接续

陈旧边、请求文件替换/内容漂移、依赖变化、超界尺寸、范围不足及重复确认在派发前拒绝。
原生写入失败后读取完整可用状态，包括 modified；不能因为体积或名称未变而登记未应用。
回复丢失或最终公共回执保存失败时，使用原 operation_id 查询，以独立证据登记后只执行剩余动作。
不自动重放，不自动删除失败特征，不清除历史 unknown。

## 原生通孔的数值比较

新毫米完整通孔预览冻结`bounded-total-v2`政策。模型长度单位和原生
`mass_properties.units`必须在创建前和写后明确证明mm及mm³，预览保留实际单位证据；
缺少或矛盾的单位读回不能补默认值。
用创建前体积减去理论去料量，得到预期剩余体积，再与实际剩余体积比较。
相对阈值仍为1e-6、绝对底限仍为1e-6mm³，同时要求绝对残差不超过0.001mm³。
两个门槛都要通过，有效预算取较小者；预期和实际去料量都必须严格大于该预算。
预览中已知无法分辨的微小去料会在派发前拒绝。创建前体积B、实际剩余体积A和理论去料量D
均须是有限正数，且D小于B。

检查仍显示理论／实际去料量，同时显示预期／实际剩余体积、残差和有效预算。
两个原生总体积相减后，小去料量的相对误差可能被放大；这不说明误差仅来自二进制减法。
体积通过也不能代替完整孔壁、闭合孔口、位置、原生定义和保护检查。
v2还核对全部物理面的实际特征归属，owner必须存在于完整特征库存中。
新增Hole所属的物理面必须完整对应匹配的内向孔壁；
不能把额外错误面过滤掉后通过，也不能把轴或基准当作孔壁。

非毫米及旧计划维持原去料差值比较。查询复用保留的政策；缺少新政策时走legacy，
不为旧失败计划补上新政策。未知或半缺的新政策保持不完整，原失败回执不变。
这些阈值是限定原生数值判据，与前文独立STEP的0.05mm³阈值分开，也不是制造公差。

螺纹、沉孔、沉头孔、其他摆放形式、变半径及复杂拓扑没有本轮新增原生验收。
既有接口声明和夹具测试不代表这些变体已经真实通过。完整证据与最终源/构件绑定以本轮交接为准；
保持 beta 和全树 FCC partial。

## 新通孔的旧实体保护

新毫米完整通孔另冻结`retained-solid-boundary-v1`，不改变v2体积阈值。
范围限定为独立非家族零件、一个活动实体、两个可完整读取的平面端面，
以及跨越整个厚度的平面或轴向圆柱侧面。预览必须证明孔圆盘位于已知材料内，
并避开已有圆柱的保守整圆排除区。复杂非凸裁剪、身份不明或字段缺失时拒绝。

全部旧物理面的引用、ID和owner必须保留。未受孔影响的面和全部旧物理边严格保持；
两个端面只允许各减少πr²面积，并增加已验证的闭合孔口。
新增物理面只能是目标孔壁，新增边只能连接这些孔壁与冻结端面。
额外合法旧owner的面、无关面的变化、额外特征或实体均不能借体积预算通过。
合法内核若重建编号而无法证明身份，本范围也保持不完整，不猜拓扑映射。

端面面积预算单独冻结：2e-9mm²加8个原值／预期值ULP，硬上限1e-6mm²。
该预算只处理已声明的序列化和数值表示，不是面积或制造公差，也不用于无关面的比较。
当前R5没有逐项记录orientation getter是否成功；有限几何检查不证明所有getter来源完整。
完整工程材料、装配、图纸和保存状态仍需各自独立验收。

正常确认和query／resolve共用冻结保护判据。没有该政策的旧意图仍显示legacy检查，
但不能据此新登记完整applied；旧回执和既有登记保持。
源码反例、最终EXE受控测试与原生正例分别记账，实际完成范围见本轮交接。
