# 如何诊断未决操作并登记结果

没有`operation_id`的未决读取请见原生读请求恢复说明 (private historical record)。下文适用于已有`operation_id`的写操作；不能用写操作登记来解除未决读取。

先运行 `operation show --id <operation_id>`，查看原回执、父子关联和 `recovery_guidance`。
这一步读取保留记录，不要求原 Creo 实例在线，也不把原 unknown 改成成功。
show没有记录未决读取，只说明这份写历史中没有对应证据，不能证明原getter已经结束。
独立query或resolve失败时，读取证据可能另存于`operation-queries`；证据留存失败也可能没有可用ID。
不要把写回执或本地历史当作原生读取状态的完整清单。
没有目标的 session、context、doctor 提示只列出未决记录；是否与新任务冲突，以该目标的实际预览为准。

若已知原生读取未决，或尚不能排除原调用仍在运行，先停止向该实例发送CAD请求。
此时只用本地show、process-only health和OS观察保留现场。
这些观察不能证明getter完成；必须用独立证据确认原调用已结束及原实例状态，才能进入工程读回或证据登记。
针对CAD工程状态的`operation query`会调用CAD getter；部分`operation resolve --dry-run`及确认也会调用getter。
下表中的安装和新式导出文件查询只读本地文件，仍不能证明原调用结束。
因此，show中的恢复命令只是满足前提后的入口，不能用它们补读来判断未决getter是否已经结束。
没有已知未决读取时，普通unknown写回执仍按目标和实际证据恢复；unknown本身不代表永久停止所有CAD。
这里没有新增跨进程锁或解除命令，新Client和新CLI进程也不能证明原调用已完成。

## 选择正确的观察对象

| 原操作 | 当前观察 | 前提与边界 |
|---|---|---|
| `service install` | `operation query --id <id>` | 省略 `--model`；先校验实际安装路径的当前 observe 根和目标选择器，再读文件；不需要 CAD 或写权限 |
| 有完整保留归属的新式 `artifact export`（含内部记录名`model export`） | `operation query --id <id> --model <原目标.prt/asm/drw>` | 不读CAD；仍明确原模型以核对归属。当前observe授权只允许检查该记录绑定的精确stage和输出文件，核对文件身份及文件头。不能证明原生调用结束，不自动发布、重导或登记 |
| CAD 操作，包括 `material assign` | `operation query --id <id> --model <原目标.prt/asm/drw>` | 先满足上述读取前提，再核对原目标实例的独立证据；材料源MTL不会将赋值变成安装文件操作 |
| 有界 `model discard` | 同上，仍明确原目标模型名 | 允许观察目标已离开会话的情况，但同时核对保留磁盘基线、其他模型和窗口；query 不自动重开 |
| 历史记录缺少归属或足够证据 | 保留 show 与 query 的 incomplete/unknown | 当前目录或新实例里看不到对象，不能证明历史操作没有应用 |

查询保存独立观察，不解除阻断。文件 saved 只证明已确认的持久化事实；组件加载、工程正确性和图面可读性需各自验证。
导出文件的生成、发布、结构化消费通过和几何通过必须分别记录。
导出show只显示已有阶段及文件归属，不新增工作区读取。
新式导出query核对精确文件，不扫描目录来猜产物；存在文件也不自动证明归属或完整原生结果。
导出完成后验证或回执失败时保留已生成的stage与已发布文件，不清除失败证据，不重新执行导出。
成功发布使用硬链接；stage和output是同一文件的两个名字，共享inode，不是独立备份。
从任一名字原地修改内容都会影响另一个名字。保留摘要描述当时的字节，不能代表修改后的当前文件。
query重新读取精确路径及当前摘要；内容改变时发布证明不完整，不升级原回执、不登记成功，也不自动重导。
外部消费者失败不倒改原导出回执。旧回执仍保留原文件及文件头检查范围；缺少完整归属的旧记录不能补成新式证明。
当前STEP工程验收仍在结构化加载阶段受阻，导出query的文件检查不解除该边界，也不能用于自动resolve。
验证不完整、回执未知、部分完成和结果登记完成不能统称成功。
若文件已经复制后观察授权才撤销，查询仍拒绝，但原操作必须保留派发事实和验证未知。
恢复授权后独立查询并按证据登记；权限错误不能把已发生的复制变成“未派发”。

## 依据证据登记，再安排剩余工作

满足上述读取前提后，迁移后的公共记录使用：

```powershell
./creo-cli.exe operation resolve --id '<id>' --outcome '<applied|not_applied|partial>' --evidence '<独立观察和依据>' --dry-run
./creo-cli.exe operation resolve --id '<id>' --outcome '<相同结果>' --evidence '<相同依据>' --confirm '<预览令牌>'
```

只登记有独立证据支持的结果；安装、孔／圆角、回转／基准、视图删除、有界模型管理、家族表和抽壳具有各自的当前证据门禁。
证据不足则保留 unknown。
家族表核对修改前冻结的完整表格、默认继承语义和成员的真实generic归属。
抽壳核对冻结的移除面、厚度、完整实体区域和保护状态；特征getter或体积相符不能单独登记applied。
登记保存原回执并解除相应门禁，不代表原操作自动通过验证，也不会重放、回滚或续跑。
workflow 必须分别检查父记录和子记录，新任务只包含明确剩余动作。

视图删除和模型管理登记后，show 的 inspection 摘要核验保留证据 ID／摘要，并显示登记结论、
来源和检查范围。证据缺失或篡改不抹掉原登记，却会阻断冲突写入。原始记录没有完整图元等字段时，
不能冒充新合同下的完整证据。名称实际改变但 modified=false 时也不能推断已保存；
即使已独立登记 applied，普通 close 仍需匹配的随后保存证明，或另行明确选择危险 discard。

旧 lifecycle 记录才使用 `--decision`、`--note`；优先按 show 给出的 `accept-observation` 指引和 query evidence_id 登记。
不要把 legacy 参数用于公共记录。旧路径仍由全局未决门禁保护；没有可靠身份的旧记录也会阻断公共写入。
公共记录有可靠身份时，只阻断冲突对象及依赖，文件目录还覆盖其祖先与后代，不自动阻断无关兄弟目标。
