# 给矩形壳体增加一条加强筋（候选）

本文供已熟悉公开CLI写入流程的工程师使用。现有`feature rib`候选只支持矩形开口壳体内的一条横向直筋。
它连接两个X向内壁和底面。本文列出操作要求；实际执行过的变体以交付索引为准。
源码测试、最终EXE原生验收、独立使用、STEP检查和PDF目视分别统计。保持beta和FCC partial。

## 适用范围

使用新自有副本。目标必须是独立、非家族、毫米单位的零件，只有一个活动默认实体。
可见实体构造必须依次为一条可编辑拉伸和一条已证明的均匀向内矩形抽壳，不得含关系式。
壳体开口位于模型最大Z。完整当前边界和原生Shell定义必须共同证明两内壁、底面和开口。
上一轮抽壳创建证据不能自动证明增加加强筋后的组合。

草绘只接受两个点构成的单条水平直线。其平面必须是实际法向为+Y的XZ基准面，朝右参考是实际法向为+X的基准面。
草绘坐标因此为+u沿+X、+v沿-Z。`TOP`和`RIGHT`只是常见名称，仍要读取实际几何。
两个请求端点都须在腔内，Z相同，且位于底面之上、开口之下。
厚度只接受正整数毫米，`side`只接受`symmetric`；厚度两侧都须与Y向内壁保留空腔。
多段线、三角筋、曲面、拔模壳体、单侧厚度、额外实体、家族组合和workflow均不在本候选范围。

## 冻结请求

先读取目标的`model show`、`feature list`、`geometry list`和`dimension list`。
记录原始文件、尺寸、材料、其他受保护模型和实际基准。保持请求文件及其文件身份不变。
公开preview保留原请求，并显示实际将使用的两端点、左右内壁和底面ID、草绘frame及填充方向。
端点按完整壳体内壁解析，不靠射线的宽容差选择。确认后不能再延伸端点或换填充侧。

以下是本轮冻结需求的预期值，不是已执行记录：外形50×30×20mm，边界为`[-25,-15,-20]..[25,15,0]`，壳厚2mm。
若实际`TOP`位于Y=0且法向+Y，`RIGHT`法向+X，请求为：

```json
{"units":"mm","name":"RIB","thickness":2,"side":"symmetric","fill":"left",
 "sketch":{"plane":"TOP","orient_ref":"RIGHT","points":[[-15,6],[15,6]]}}
```

原模型端点为`[-15,0,-6]`和`[15,0,-6]`。实际草绘端点应为`[-23,6]`和`[23,6]`，
模型端点为`[-23,0,-6]`和`[23,0,-6]`。筋从Z=-6向-Z填至Z=-18的底面。
该顺序的`fill`是`left`；反转端点顺序则是`right`。
省略`fill`时，preview解析并冻结唯一朝底方向；不是确认后先试一侧再试另一侧。
请求指定反方向时拒绝派发。Java只尝试一次创建，不通过删除后重建来猜方向。

名称也属于冻结意图。指定名称时，独立新增特征清单必须按Creo的大小写无关规则匹配。
省略名称时明确保留原生默认名称，不授权后续改名。
独立名称字段已读但值为空时保留原值；缺少该字段的读取仍是不完整。

## 确认与读回

按当前授权设置`CREO_CLI_SCOPE_FILE`，执行原请求的dry-run，再使用同一请求及返回token确认。
保留preview分配的operation ID、输入身份和回执。下列尖括号内容须换成实际值。

```powershell
creo-cli feature rib --model <实际零件.prt> --request <请求.json> --dry-run --compact
creo-cli feature rib --model <实际零件.prt> --request <请求.json> --confirm <返回token> --compact
```

独立读取`feature show`的`native_definition`、`native_section_readback`和`native_solid_geometry`。
`projection_refs`的9列、原生角色编码、实体总数和旧新增计数的区别见草绘读回字段附录 (historical material retained outside this snapshot)。
原生Rib类型、活动状态、名称、选中实体、厚度、厚度侧、填充侧、基准引用和真实草绘线段都须匹配。
两个请求的草绘投影引用须读到真实原生surface ID、类型、所属模型及空装配路径。
原生草绘实体清单必须与独立读取的实体总数一致，每个实体ID的角色都须可读。
Creo自动生成的左右墙辅助线也要读取其projection或construction角色。
这些辅助线仅可对应冻结的两面墙。
只比较投影显示名称、空间位置或创建时传入的references不能替代实际选择身份。
厚度驱动尺寸必须有真实ID，且与原生树和实体读数一致。
不能假定原生筋厚元素一定提供dimension ID。独立枚举筋特征的尺寸，核对所属特征、当前可访问性、
线性类型，以及非参考、非关系式驱动、位于草绘区段之外等条件，必须只剩一个驱动尺寸。
再与原生树厚度和完整实体读数交叉核对。不能仅按数字相同选尺寸，也不能把无类型零值辅助尺寸算作驱动尺寸。
读取缺失或候选不唯一时保持不完整，不重新创建来补证。
预览还冻结最多一个隐藏辅助datum的规则。独立检查其父引用、唯一Rib子依赖、共面几何和非实体性质。
这证明本候选允许的辅助效果，不宣称SDK已提供容器归属。其他新增特征仍拒绝。
完整平面区域、闭合轮廓、每条边的两个归属面及全体面连通关系共同证明壳体与筋的并集。
还须核对原Shell定义、外壳、开口、剩余空腔、原尺寸、材料、来源、其他模型和磁盘文件。
体积增加、包围盒或特征数量不能替代这些检查。错位置、错方向、缺少壁底连接、额外实体和陈旧引用不能完整通过。

## 厚度和保存重开

从独立读回取得真正的筋厚尺寸ID。用公开`dimension set`预览并确认2mm改为3mm，再改回2mm。
每次都重新读取原生定义、实际厚度、位置、填充方向、连接和完整保护几何。
上述需求的预期总体积依次为9576、10128、9576mm³；这些值只是补充检查，不是制造公差。

明确保存所有相关自有模型，检查实际文件版本及modified状态。
按依赖顺序正常关闭全部相关自有模型，再从保存文件重开。独立确认筋和驱动尺寸仍可读、实体仍匹配。
重开后完成一次获准的尺寸编辑并返回目标值，再保存和检查。不要把保存回称或会话中仍有模型当作重开证明。
历史模型、旧unknown和失败原件继续保留；本候选不扩大`model discard`或特征删除范围。
旧请求若未冻结辅助规则，不能据新规则补记applied。完整实体、名称和保护状态足以证明实际部分改变时，
可明确登记partial并单独保存失败模型；原始失败回执仍保留，不改名或重建来修复验证错误。

## 图纸和STEP

图纸只增加本任务需要的关联视图和尺寸。先查看可检测的视图、尺寸和图元冲突，再安排位置。
REF必须保留。缺少文字框时，不能把空框当零尺寸，也不能登记自动布局通过。
导出后实际查看PDF每一整页，检查文字、箭头、轮廓、尺寸与REF；原生读回不能替代图面查看。

用新路径导出STEP，并由独立消费者检查毫米单位、单个有效实体和完整几何。
消费者从冻结需求建立壳体与筋的预期并集，分别检查“STEP减预期”和“预期减STEP”的完整布尔差。
在声明的比较精度内，两边都须为空；同时保留有效性、实体数、边界和体积结果。
抽样点、总体积或外框相同不能替代全体几何差。STEP不证明Creo特征历史、可编辑性或材料，应分别原生读取。

## 失败后的观察

丢回复、验证失败或回执存储失败后，先停止冲突写入。新CLI进程先用`operation show`读取原记录，
再对原模型运行有当前授权的`operation query`。`prismatic_rib_verification`按保留的原请求和实际决定独立检查当前实体。
`operation resolve`只登记足够证据支持的结果，使用同一名称、几何、来源和保护判据。
登记后的`prismatic_rib_inspection`分别显示历史证据完整性和当前充分性。

几何正确但名称错误也不能登记applied。证据不足时保留unknown，已观察到部分变化时如实登记partial。
query和登记不改名、不重建、不重放原操作；历史回执不倒改为通过。
新实例中没有原模型，不能证明旧操作没有执行。后续只安排明确剩余动作。

先完成独立query和证据支持的resolve，再单独预览并确认save。
恢复判据会核对冻结时的磁盘版本；提前保存会改变保护状态，不能再直接使用原来的完整证明。
如果证据不足以登记，保留阻断和现场，不能用保存或重新创建绕过。
登记applied只说明当前证据支持已发生的改变。
它不会把原unknown回执改成成功，也不证明saved。

保存状态要由实际原生文件、版本、modified读回及正常保存重开证据分别说明。
几何正确、服务返回成功或会话中仍有模型，都不能证明保存或重开完成。
保留原请求、派发见证、失败回执和后续查询证据；继续使用原历史目录和授权范围。
