# creo-cli 0.2.0 开发交接

版本：**0.2.0 源码开发版**。发布等级：**unpublishable**。

本轮按“借鉴已发布接口，在没有真机环境时尽量推进真实操作能力”的方向继续实现，
不以缺少 Creo 为理由停留在调研，也不把替身测试包装成真机验证。
本轮没有创建/推送 GitHub 远端，没有发布 npm、PyPI、二进制或 Release。

## 一、相对 0.1.0 的增量

公开叶子命令由 **22 增至 75**。新增 **45 个 CREOSON 领域操作**及 **8 个连接/工作流命令**。
原有 PTC VB API 实验适配器与显式 `.creo.json` 模拟后端保留；不会自动切换后端。

| 范围 | 实现的操作与边界 |
|---|---|
| 模型生命周期 | 列出/读取/打开/显示/再生/关闭窗口/保存/备份；独立零件保存—关闭—移出内存—重开—比较观察数据 |
| 参数与尺寸 | 明确类型的参数读取、更新和显式创建；线性/半径/直径尺寸修改，检查单位和关系式冲突 |
| 特征和材料 | 读取含未命名特征的列表；精确名称隐含、恢复、重命名；选择已加载材料、读取带单位上下文的质量属性 |
| 装配和视图 | BOM 树、实例变换、单个坐标系约束或固定变换装入；列出、激活、保存模型视图 |
| 工程图 | 从已有真实模板创建；添加模型/图纸、普通视图和投影视图、读取与再生 |
| 文件交付 | STEP/IGES/DXF/PDF/JPEG 请求；先在隔离目录暂存，检查非空/文件头，再不覆盖已有文件地发布 |
| 工作流 | 最多 32 个顺序步骤、8 个明确模型目标；一次预览确认、逐步回读、持久化结果、部分失败记录与人工核对 |

新增领域命令固定走外部 CREOSON，不是任意 RPC 代理。每项操作有严格请求 schema、示例、
默认参数、来源和嵌套结果 schema。`reference --command` 从实际分派注册表生成，不解析帮助文本。

## 二、从公开项目落实到代码的经验

实际实现以 CREOSON / Creopyson 公开接口为依据，自写标准库 HTTP 客户端；不打包服务器、
Java、J-Link、PTC SDK 或厂商库。协议目标为 CREOSON 3.0.2，不代表整套能力已经在该版运行过。
来源仓库、路径、Git blob 标识与部分发布标签下的规范交叉检查记录在：
`docs/UPSTREAM_SOURCES.md` 和 `docs/evidence/upstream-interface-sources.json`。

本轮纠正了几个仅看客户端说明容易带入的假设：隐含特征不沿用截断/连带子特征默认值；
坐标系类型接受发布示例的 `COORDINATE SYSTEM` 与文档中的 `COORD_SYS`；未命名特征允许缺少
`name`；尺寸文本按发布规范作为字符串数组处理；变换返回旋转角字段也有类型说明。

发布源码中的工程图创建启用了错误对话框。这个风险已经写入机器能力描述和预览，
不会声称所有原生操作都能无界面完成。CLI 超时不等于 Creo 停止，也不会自行点击弹窗。

## 三、执行、验证与恢复

默认只读。由人配置现有可丢弃工作区并授予写权限、实验性原生写入开关。
连接身份、工作区、明确参数、观察状态及输入文件散列绑定到限时、单次 HMAC 令牌。

HTTP 连接在单条命令内复用，各子请求共享剩余时间预算，禁止代理、远端地址、重定向和自动重试。
本地散列/文件系统操作并不受该定时器硬中断；另有限额。锁只能协调本 CLI，不能阻止 GUI 或其他客户端。

每次原生修改前持久记录意图。收到响应后执行对应回读；若超时、失联、回读不符或崩溃，保留
未知/部分完成状态，阻止后续原生写入。`workflow reconcile` 只记录人已检查软件且服务器空闲的声明，
不是撤销、自动续跑或软件状态验证。不能通过重发旧令牌重复执行。

保存前的字节备份只覆盖磁盘旧版本，**不覆盖未保存内存状态**。roundtrip 限制为会话中唯一的独立零件，
比较单位、参数、尺寸、可观察特征等，不证明完整 BREP 几何相同。工程图完成状态可能只有上游接受请求，
需读取 `verification.level`、`checks`、`not_checked`，不能只看 `ok` 或 `completed`。

## 四、实际执行过的验证

最终测试：**305 项通过，失败 0、错误 0、跳过 0；75/75 命令实际分派，无缺失和未声明项**。
环境：Linux / Python 3.13.5。证据：`docs/evidence/offline-tests-0.2.0.json`。
这不是完整 FCC、Windows/macOS、许可或 SDK 兼容性认证。

可重放演示运行了 **15 次真实 CLI 子进程、183 次真实本地 HTTP 请求**，验证替身中的尺寸 40→45、
保存重开后的观察数据、两个工程图视图、暂存导出和历史结果读取。证据：
`docs/evidence/creoson-offline-demo.json`。它没有使用真实 Creo/CREOSON；夹具中的模型、STEP、PDF、
图片字节特意标为无效模拟材料，不是可交付 CAD 文件。

Python 编译、版本同步、Node 脚本语法和 Git 空白检查已通过。已构建本地开发 wheel，
在仓库外隔离安装并验证模块来源、命令入口、版本、自描述与缺失配置错误。
Ruff、依赖审计、GitHub CI、独立模型 Skill 评估尚未执行。
交付清单另行记录从本轮 bundle 全新克隆后的完整复跑和产物 SHA-256。

## 五、保留的缺口与发布状态

还没有从零创建原生零件、草绘/拉伸/孔/倒角特征；未实现任意装配约束、自由度与干涉校核、
钣金展开、完整公差标注、有限元或 Windchill。未捏造可编辑模型来冒充完成。
模板路径查找、版本/类型库/许可证、特征和图纸的几何正确性、原生超时/弹窗/文件保存语义均需真机核实。

规范目标仍固定 `ai-native-cli-spec v1.6.2`，精确上游文件、生成运行时契约及完整一致性审查尚未集成。
`bootstrap_spec.py --check` 和 `release_gate.py` 实际返回阻止发布，`package.json.private=true`。
本地 wheel 仅用于开发安装，不是稳定版或公开发布。

## 六、还原与入口

优先保留 Git bundle，它含基础版本与本轮提交历史：

```bash
git clone creo-cli-0.2.0.bundle creo-cli
cd creo-cli
python scripts/test.py
python -m creo_cli reference --command "dimension set" --compact
```

源码 ZIP 可直接阅读。开发 wheel 可在相应 Python 环境中用 `pip install <wheel文件>` 本地安装；
完整 Skill、测试和示例仍应从源码包取得。以上本地自描述/测试不需要真实 Creo。

真实环境设置与操作流程看 `README_zh.md`、`docs/CREOSON.md`、`docs/WORKFLOWS.md` 和 `docs/E2E.md`。
没有随包提供真实模型或模板，需要在可丢弃环境中使用合法来源文件。
GitHub 发布脚本先运行 `python scripts/publish_repository.py --check`；只有已认证的 `gh` 和显式
`--apply` 才会创建并推送目标公开源码仓库，不 force-push、不打版本标签、不发包。
仓库介绍从 `package.json` 读取，不再手工维护第二份。
