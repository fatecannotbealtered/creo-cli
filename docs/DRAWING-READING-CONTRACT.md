# 图纸范围读取与放置提醒

本说明适用于已支持的图纸放置操作。工程师先读取实际图纸、页、视图和对象身份，
再预览。命令字段以公开reference为准，不需要开发模块或内部脚本。

## 三种事实分别记录

显示锚点是对象的放置位置，文字包络是一次读取的实际范围，PDF是已导出的显示结果。
锚点相同不能证明文字范围相同；PDF可读也不能证明全部历史时点的范围保持。
数值、公差、所属零件、页和视图仍需分别核对，不能因包络未验证而忽略这些变化。

R5通过`WDimension.GetEnvelope(drawing,-1)`取得4个屏幕坐标点，
再以`GetSheetTransform`转换为纸面实际单位，原点在纸面左下角。
不要再乘一次视图比例。官方接口说明没有给出“打开后包络已稳定”的屏障。
R5未独立记录原4点、转换矩阵或逐点完整性；其部分异常路径可能返回部分聚合框。
因此非null框也不能单独证明完整。

客户端保留这类原值，并标为`legacy_native_aggregate`、跨时点`unverified`。
两次一致最多证明这两次观测相等，不能升级为稳定、持久化或完整保护。
R31的8条尺寸框共16个坐标变化及7条非目标标注缺口继续保留；
目标孔径标注的事前范围例外不适用于其他标注。原因尚未得到可验证解释。

## 绘制前的提醒

相关公开预览的`preview.extensions.creo.layout_feedback`列出页、单位、对象、
原始范围、预测范围、已检查范围、候选冲突和未检查项。
只读`drawing layout plan`在结果中直接返回`layout_feedback`。
它复用同一份已有读回，不额外调用CAD getter。

|读取对象|可检查的有限范围|仍不能证明|
|---|---|---|
|视图|本页原生矩形范围及纸边|精确投影轮廓和全部alignment|
|普通注释、气泡文字|可读文字矩形|气泡圆圈、箭头和引线路径|
|单段表格、BOM、标题栏|有来源和页单位的完整外框|每个单元格文字是否放得下|
|R5尺寸框|本次观测的候选AABB交叠|完整包络或跨时点保持|

候选AABB相交是可能冲突，不是已证明的精确图元相交。
预测范围与原生原值分列；旧孔径文字框不能预测新孔径文字的宽度。
缺页、缺单位、零面积、倒序或非有限范围均列为未检查，不补成零框或默认毫米。
不同页的相同坐标不能相互比较。空冲突数组只说明已检查矩形没有候选冲突。

提醒还要求对象身份可唯一解析。保留原始库存的每一行及其索引，不按名称或ID静默去重。
同类且同owner的重复原生ID，以及同页重复视图名，会使相关行列为未检查。
缺所属图纸或模型、缺视图、页归属冲突也会使相关行不可用。
尺寸ID属于其模型；视图、注释和表格ID属于图纸。页号不能把重复ID变成不同对象。
跨页同名视图只有在原对象明确给出页、原生ID不重复且该页匹配唯一时，才可用于提醒。
尺寸没有页时，只能由唯一的实际视图推导；不能任选同名视图的最后一行。
尺寸所属零件不必等于装配视图的模型，但两者的实际身份都要可读。

移动预览只排除唯一匹配且与冻结原行相同的那个对象。
重复身份、陈旧原行或页冲突不会通过proposal中的新页或新位置被修好，也不会排除多个旧对象。
相关冲突无法检查时，结果要逐项列出原因；不能把失去候选范围解释为没有风险。

尺寸线和界线、引线、完整draft直线、气泡字形及圆圈、精确轮廓、部分alignment、
表格文字包络和符号显示范围仍未全部覆盖。
`whole_layout_verified`、跨时点保护和`layout_coverage.complete`保持false。
最终PDF必须另做独立解码、全页及关键局部目视，不能升级旧REF或incomplete回执。

## 正常视图与爆炸表达的独立读回

装配当前爆炸状态、图纸视图是否采用爆炸表达、该视图显示哪个模型，是三项不同事实。
`Assembly.GetIsExploded`有assembly-mode适用条件。新组件依据实际当前模型及当前窗口所属模型
记录上下文；已知图纸语境的值不作为实际装配显示证明，缺失或失败也不补false。
完整named-state库存与display读回完整性分列，逐视图Boolean仍独立读取。
命名状态的名称和移动列表从装配的完整`model show.explosion`读取。
新组件支持的视图行另外报告`view_identity_readback`和`exploded_display_readback`。
后者的原生来源为`WView2D.IsExplodedState`，只证明该视图的Boolean显示标志。
名称、ID、页和显示模型分别注明getter来源，不能从请求参数或setter回复补值。

当前未建立受支持的逐视图命名爆炸状态身份读取方式。
`named_exploded_state_reference`保持`not_checked`；装配活动状态不能代填此字段。
Boolean为true也不证明该视图永久绑定某个命名状态，或后续编辑会自动更新其投影。
同页正常与爆炸视图应逐一核对实际身份、标志、投影及保存重开后的结果。
接口支持逐视图标志，不等于某一工程已完成同页原生验收。

R33 P2保留了一个实际反例：独立getter确认正常视图false、目标视图true，
但两者实际投影仍为同一装配堆叠。一次标准现有视图更新后也没有分离。
原selected-check回执保持原意，工程分离验收另列失败，不能从Boolean升级结论。
同次对照后，图纸语境下的组件position、path transform和bbox原值发生变化，
约束和命名状态库存保持；这些数据既不证明正常放置安全，也不证明实际工程损坏。
没有再读到相等，没有舍入、放宽比较或删除原始失败。详见[R33证据](https://github.com/fatecannotbealtered/creo-cli/blob/c0f5b8ed60cfe7a7f6e51639c391b0f9140bfc6d/docs/evidence/round33-20261018/README.md)。

带此能力的新组件在创建后通过独立`model show`寻找唯一新增原生ID，
检查实际图纸、页、模型及爆炸标志，并保留旧视图和旧资源。
普通R5非爆炸视图仍可走原有范围；旧R5不具备上述新字段，不能借用新组件的结论。
使用`--exploded`需要实际加载支持该读回的组件，以公开能力及构件绑定为准。
明确的爆炸视图还需要装配上下文读回能力。创建指令与最终显示设置分开，最后仍须独立getter通过；
创建成功但Boolean错误会留下真实新增视图和失败回执，不自动重建，也不因PDF外观升级原回执。
普通已返回的getter失败保留缺项，不填false；真正pending仍按下节停止。

## 有限对照和停止条件

对准确保存图纸的自有副本，先保留正常open即时回复，再串行读取一次model show。
两次之间不移动标注、不隐式刷新或再生成，不重复轮询直到相等。
只有存在正式依据及明确工程收益时，才预先声明一次显示／再生成操作及其可能的dirty影响。
当前公共`model regenerate`只适用于Solid，不能当作图纸再生成入口。

普通已返回的Unsupported或BadInputs是读取缺项；可能仍未结束的读取则必须停止该实例CAD派发。
保留原错误、请求关联和停止指引。新Client、增加timeout、process-only健康或修复目录权限
都不是恢复证明。先独立确认原调用和实例状态，才能继续工程读取。
