## [1.0.0] - 2026-09-29

The first release. creo-cli was rebuilt around one engine -- a service that runs inside
Creo -- and a command tree shaped by what an engineer does
(`docs/adr/0002-one-engine-intent-shaped-tree.md`). An agent can take a part from nothing
to a drawing and an exchange file, assemble parts and check them, and every step is
previewed, confirmed once, read back from Creo and recorded. The 1.0.0 version line of
2026-09-18 was never released and is replaced by this one.

### Added
- **A service inside Creo.** `service/` is an Object TOOLKIT Java application Creo loads
  from `protk.dat`; it listens on `127.0.0.1:9057`, requires a per-start token, and runs
  named operations on Creo's own thread (protocol 2). Work whose caller gave up before it
  started is withdrawn, and the reply says whether it started. A small C library draws
  the sketches Object TOOLKIT Java cannot: it projects the references Creo requires for
  sketches of several entities, and draws the centerline a revolve turns about. It also
  places a drawing's dimensions, reads back where they are, and deletes one made on the
  drawing -- calls Java lacks, or has only in forms that read back wrong or do nothing.
- **The command tree**, 82 commands, every one `<noun> <verb>`: `session status|cd`,
  `workspace list`, `model list|show|open|import|save|close|discard|render|export|set-tolerance-standard|set-common-name`,
  `part create`, `feature list|show|extrude|revolve|datum-plane|datum-axis|round|chamfer|hole|thread|shell|draft|rib|sweep|pattern|mirror|delete|suppress|resume|rename`,
  `geometry list|measure`, `dimension list|set|tolerance`, `parameter list|set`, `relation list|set`,
  `family-table show|set|remove`,
  `material list|assign`, `assembly create|add|replace|explode|remove|check`,
  `drawing create|add-view|move-view|annotate|hide-dimension|move-dimension|add-dimension|add-datum|add-gtol|add-note|edit-note|add-table|add-title-block|move-table|add-bom|add-balloons|add-symbol|remove`,
  `workflow run`,
  `service install`,
  `operation list|show|acknowledge`, and `reference`, `context`, `doctor`, `changelog`.
- **Parts from nothing.** `part create` takes explicit units (`mmns`, `inlbs`) or a
  template in the workspace -- never Creo's default template, which may be an inch one.
  `feature extrude` sketches a circle, ellipse, rectangle (corners rounded or not), polygon,
  slot, or an outline of lines and arcs -- any but the ellipse with holes inside it -- on a
  datum plane and adds or removes material, one side, the other or symmetric; `feature revolve` turns a
  profile about a centerline in the sketch or an axis of the part. A request states its
  units; a millimetre request on an inch part is refused, never converted.
- **The features a part is made of.** Datum planes (offset, or through an axis at an
  angle) and axes (two planes, an edge, a cylinder); rounds and chamfers on edges named
  by the ids `geometry list` gives, a chamfer square to its faces made so a drawing calls
  it out 1 X 45°; holes placed by distances from two references, on a bolt circle about
  an axis, or on an axis, blind
  or through all -- straight, tapped for a screw or clear of one at a close, medium or free
  fit, sized from Creo's own hole charts (ISO, UNC, UNF), counterbored or countersunk from
  the chart or by hand, each read back by its radii; cosmetic threads on a shaft or in a
  bore, from a face to a depth, at the minor or major diameter the chart's size implies;
  shells that remove the faces named; drafts that tilt faces about a hinge
  plane by an angle measured from the pull direction, as a molded or cast part needs, each
  face read back at the angle asked for; profile ribs -- an open chain sketched from face
  to face, filled up to the part on the side it closes, thickened about the plane or to one
  side of it; sweeps -- a closed section along a smooth path of lines and arcs sketched on a
  plane or face, the section's place stated in the path's terms and its volume Pappus';
  patterns along a direction -- or two, a grid -- or
  about an axis, the instances counted; the whole part mirrored about a plane. Suppress,
  resume and rename; delete takes its children, listed in the preview.
- **Views that land on each other.** A view added or moved is read back against the others
  on its sheet, and any it overlaps are named with the move that clears them.
- **Geometry picked by where it is.** `geometry list --near x,y,z` lists the nearest first,
  each with its distance, so a face or an edge is named by a point on or near it.
- **A turned part's diameters over their steps.** `drawing dimension annotate` moves each diameter of
  a revolve over the step it measures, halfway between the axis and the edge, as a shaft is
  drawn; Creo's spacing had stacked them all beside the view.
- **A drawing a drafter would sign.** `drawing create` lays out `FRONT`, `TOP`, the side
  view and `ISOMETRIC` where the sheet's projection puts them -- Creo's ISO sheets first
  angle, the top view below the front; its ANSI sheets third angle -- named the same in any
  language, the bottom right corner left for the title block (`--projection first|third`,
  `--views template|none`; the reply's `projection`). `drawing dimension annotate` moves a diameter
  Creo showed on a circle its view cannot see -- a hub behind its flange -- to a view that
  sees the cylinder, gives a patterned hole's diameter with the count, 6X ⌀11, brings back

  view's scale -- stay legible.
- **Workflows.** `workflow run` takes several writes, previews them together and runs
  them under one confirmation; each step is planned when it runs, read back and recorded
  as if run alone, and the first failure stops the rest (`stopped`) and keeps what ran.
- **Installing the service on another machine.** `scripts/build_bundle.py` packs the
  jar and the library a licensed machine unlocked, with a SHA-256 manifest;
  `service install` checks a bundle against it and the protocol, installs it into
  creo-cli's own directory and writes the `protk.dat` Creo loads it from. Registering it
  with Creo (one `config.pro` line) stays the user's step, and `doctor` names it.
- **Every write previewed against a live reading, confirmed once, read back and
  recorded.** The preview reads Creo and says what the write will do there -- units,
  planes, the profile's area and the volume change it implies, the features a delete
  takes with it, the version a save will write. The token is bound to that reading and the
  policy; a model edited in the GUI in between makes the confirmation fail. Confirmed
  writes return `verification.checks` (postconditions read back from Creo; a failed one
  is `E_VERIFY_FAILED`) and `observations` (measurements that inform, such as the signed
  volume change beside the expected one: area x depth, Pappus, the removal of a round).
- **Receipts.** Every confirmed write leaves one in `operations.sqlite3`; a write whose
  outcome is unknown, partial or unverified blocks further writes until a person records
  what they saw with `operation resolve`. A failure Creo reports is settled by reading
  the target again: `failed_unchanged` if it is as before, `partial` if not.
- `--dangerous`, a second gate on both steps of `feature delete`, `model discard` and
  `assembly component remove`, and `dangerous: true` for them in `reference`.
- `--request -` reads a request from stdin.
- `reference` marks each command `live_verified` (null for commands that never talk to
  Creo) and `uses_creo`; `tests/test_contract.py` holds every mark to a successful call in
  `docs/evidence/live-creo.json`.
- `reference --command drawing` gives a noun's commands; `reference --fields
  version,commands.path,commands.description` is the whole tree in 14 KB.
- `--fields` on a list takes item fields directly: `model list --fields model,type`; a
  field some items lack is left out of those, and one the output does not have is named,
  with the fields it does.
- `doctor` checks the toolkit, the Java Creo starts the service with, the service
  (protocol, creation API, sketch library) or else an installed bundle, Creo's working
  directory, the workspace, the policy, release readiness, and whether an installed copy
  of the Skill needs a newer binary -- each with a fix.
- `scripts/record_live.py` runs every command that talks to Creo, with every option its
  request and flags declare, as a real subprocess against a live Creo 13.4.1.0, and
  records each call and the checks made on it. Creo measured a 40 x 20 x 10 block at
  8 000 mm³, a 6 mm hole at −282.743 (π·9·10), a revolved shaft within 1e-16 of Pappus, a
  torus turned about a datum axis within 1e-16, an outside shell at exactly its walls, a
  mirrored box at twice its volume, and two pins that clash at exactly π·25·10 of shared
  volume.
- `geometry list` reports coordinate systems, the references a `csys` constraint takes.

### Changed
- Writes act only on models that live in `CREO_CLI_WORKSPACE`: Creo stores a model back
  where it came from, so a model opened from elsewhere is refused by every write that
  changes, saves or closes it -- and as a component or the model of a drawing, since saving
  an assembly stores its changed components too. An export only reads its model.

### Removed
- The CREOSON route (156 commands), the VB API adapter and its JSON mock (11 commands),
  and `system capabilities`, `snapshot *`, `change *`, `workspace inspect`, with their
  contracts, generators, examples, documents and evidence. Git history keeps them.

## [0.2.0] - 2026-09-18

### Added
- Independent loopback CREOSON transport with persistent connection, explicit session setup, bounded requests and no automatic retries.
- 45 typed CREOSON domain operations for files, parameters, length dimensions, feature states, materials, assembly, views, drawings and staged exports.
- Guarded isolated-part save/close/erase/reopen comparison of observed design data.
- Bounded native workflows, durable partial/unknown receipts, separate hash-verified step results and human acknowledgement of unresolved state.
- Per-operation source provenance, request examples, safe defaults and nested result schemas.
- Stateful HTTP-substitute contract tests and executable subprocess workflow evidence; no real Creo evidence is claimed.

### Changed
- Public command registry expanded from 22 to 75 leaves; original VB API and explicit JSON mock routes are preserved.
- Documentation now distinguishes backend implementation, upstream acknowledgement, selected postconditions and real deployment evidence.

### Security
- Native mutation guards bind session identity, workspace, exact requests, selected observed state and input hashes.
- Exports use isolated staging plus atomic no-clobber publication, rather than trusting an upstream overwrite check.
- Unknown native write outcomes stop automatic work; feature clipping/child defaults, wildcard targets and GUI-selection fallback are refused.
- Session identifiers are redacted from CLI output and native receipts; package remains unpublishable pending spec conformance and live evidence.

### Fixed
- Match released CREOSON response shapes for coordinate-system names, unnamed features, dimension text arrays and transform rotations.
- Surface upstream drawing-creation modal-dialog risk in machine-readable reference and previews; never confuse HTTP timeout with native cancellation.

## [0.1.0] - 2026-09-17

### Added
- Registry-driven JSON CLI with self-description, bounded queries and projected fields.
- Portable snapshots, identity-based comparisons, and explicit simulation fixtures.
- Restricted parameter and linear-dimension ChangeSets with expiring HMAC confirmation.
- Durable replay prevention, cooperative resource locking, backups and redacted audit history.
- Experimental Windows PTC VB API worker with session-bound observation checks and no implicit saves.

### Security
- Native is the default backend; native failures never silently select simulation.
- Writes default to disabled; native modifications require a second human opt-in.
- Release is unpublishable pending complete conformance and recorded live Creo evidence.

### Fixed
- Separate the internal command dispatch namespace from the public reference command filter.
- Preserve structured test evidence when live capability enumeration fails.
- Refuse repository publication from a parent checkout, non-main branch, or conflicting check/apply modes.
